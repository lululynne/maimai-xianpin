## 一、审读：方案要补的六处

1. **方案没写后端。** 「拼单广场」要让同一家店的陌生人互相看见，必须有一个共享的服务端和存储，纯前端做不到。定：一个 TypeScript 服务，用 **Hono**（本地 Node 能跑，日后也能原样上 Cloudflare Workers），存储 **SQLite**（表结构写成 D1 也能吃的 SQL）。前端是同一服务吐出的静态页。
2. **麦当劳 Token 是梅宝本人账号的钥匙，只能在服务端用，且只许调门店级只读工具。** 所有访客的查询都走她这一把钥匙，所以：
   - 允许：`query-nearby-stores`、`query-meals`、`query-meal-detail`、`calculate-price`、`query-store-coupons`、`now-time-info`。
   - **禁止对访客暴露**：`query-my-coupons`、`available-coupons`（若实测是按账号返回）、`create-order`、任何带她个人信息/订单的工具。方案第 3 节第 9 条写了 available-coupons，实测确认它是门店级才可用，否则删掉。
   - 菜单/价格按门店缓存 10 分钟，别让评委一刷就打她的配额。
   - Token 只放 MacBook 本地 `.env`（已 gitignore），仓库里只有 `mcp-config.example.json` 占位符。不进客厅、不进任何群。
3. **「按真价格算每人该出多少」没有算法。** 套餐里单件没有单独标价。定规则：每人那份 = 套餐总价 × (他那几样的单点价之和 ÷ 全部单件单点价之和)，按「分」取整，零头归发起人。单点价用 `calculate-price` 逐件实测；查不到单点价的件按均分处理并在卡片上注明。写成纯函数 + 单测。
4. **演示模式要提前，不是 10-22 才做。** 评委打开时店里不会真有陌生人在拼，广场是空的就什么都看不出来。演示模式 = 用 T0 抓下来的真实菜单夹具 + 自动生成几单「别人正在拼」的单子（昵称、尾号全假），计时可加速。它是作品第一印象，第二天就要能跑。
5. **防乱占位。** 只靠「填尾号后四位」，谁都能把别人的单占满。v1 最低限度：每个浏览器一枚匿名设备号（cookie），同一设备不能拼自己发的单、同一尾号不能在同一单出现两次；同一设备 10 分钟内最多加入 3 单；发起人可以踢掉未确认的人。不做登录。
6. **隐私留存。** 只存昵称 + 尾号后四位 + 设备号；单子结束 24 小时后自动删除。页面上任何地方都不显示完整手机号。

其余（只到店自取、不碰支付、券档只展示不发、不提别的牌子、规定时间 10–60 分钟默认 30 不可延长、相似拼单弹窗最多 3 单按截止最早排）按方案原文做，不改梅宝定的规则。

## 二、施工单（按顺序；括号是建议日期）

**T0 · MCP 探路（10-18，最先做，其余都靠它）**
- 前置：梅宝在 open.mcd.cn/mcp 自己登录、激活、同意协议、复制 Token，直接贴给 MacBook 这边写进本地 `.env`。这一步只能她本人做。
- 跑 `tools/list`，把真实工具名和入参/出参 schema 原样记进 `MCP_INTEGRATION.md`。
- 对三乡四家店（1420082 / 1420800 / 1420277 / 1421248）各调一遍允许清单里的工具，脱敏后存成 `fixtures/`，演示模式就用这些。
- 实测确认：菜单有没有价格字段、套餐明细能不能拆出单件、`calculate-price` 单位是不是「分」、`available-coupons` 是门店级还是账号级。
- 回执里写清这四个答案。

**T1 · 骨架（10-18）**
- Hono + TS + SQLite；`MCD_MODE=live|demo` 切换；MCP 客户端封装成一个接口，live 和 demo 两个实现，上层不知道差别。
- 一条命令起服务；`npm test` 能跑。

**T2 · 门店与套餐（10-19）**
- 接口：附近门店、某店可拼的大套餐列表（套餐件数 ≥ 2 或价格高于阈值，阈值写配置）、套餐明细、价格复核。走缓存。

**T3 · 分摊算法（10-19，纯函数）**
- 按第一节第 3 条实现；单测覆盖：整除、有零头、某件查不到单点价、只剩发起人一人。

**T4 · 拼单状态机（10-20）**
- 状态：拼单中 → 已满 → 已下单 → 已取到；或 拼单中 → 到点下架（转单点）。
- 规则：规定时间 10–60 分钟、默认 30、发起后不可延长；到点不管拼没拼成都结束；防乱占位按第一节第 5 条。
- 过期处理：读的时候惰性判过期 + 每分钟一次清扫。

**T5 · 广场与相似弹窗（10-20）**
- 每店一个列表，按截止时间最早排，前端每分钟刷新。
- 发起前查同店同套餐在拼的单，最多 3 单，按截止最早排；文案照方案 3.5 节原样。

**T6 · 卡片、提醒、计时、下架（10-21 ～ 10-22）**
- 每人一张小卡片：自己那份有什么、该出多少、尾号。
- 「已取到」：发起人点一下，其他人页面轮询（30 秒）收到提醒。不做系统推送。
- 等待计时只算取餐时间之前那段，旁边显示按理想版能拿哪档券（15 分钟 2 元 / 30 分钟 5 元），只展示。
- 到点没拼成：列出单点价，再只读查一次门店券，有就提醒一句；不领券不绑券。

**T7 · 演示模式（10-19 起就要能跑，10-22 收尾）**
